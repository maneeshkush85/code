## High-level view

All six v1 issues are resolved in code, not just in documentation. The two assumptions that made the old mapper unsafe — "JSON input-slot index == INPUT_TYPES ordinal" and "`widgets_values` is a positional arg list" — are both gone from the primary execution path. Link inputs now resolve by socket name, and the three custom nodes get explicit, name-anchored kwarg construction that refuses to back-fill anything it cannot match by name (leaving the node to apply its own default). It stops short of ComfyUI's own PromptExecutor, and the script now says so plainly.

The unlinked-optional-socket concern (issue 4) is handled structurally: `_resolve_node_inputs` only iterates linked slots, so `optional_latent`/`global_prompt` never enter `resolved_inputs`, and the LTXDirector branch additionally pops them defensively. No positional fill can reach them anymore.

The checkpoint layer is now honest rather than aspirational: `_try_restore` returns True only when a live output is cached in the current process, and a restarted run logs that it is re-executing because tensor outputs are not serializable. The `CheckpointManager` docstring was rewritten from "skip re-executing expensive nodes" to "progress log, not cached compute."

The Stage-1/Stage-2 labels remain faithful to the JSON (base pass = node 133 @ guide 0.5 / 8 steps; upscale pass = node 132 @ guide 1.0 / 4 steps), and the added comments tie each label to its node ids and strengths and flag the inversion against the task description's "1.0 and 0.5" reading order. The residual items are two small speculative bindings in the new custom-node code, neither of which can silently corrupt execution.

### Issue 1 & 2 fix — name-based link resolution plus explicit custom-node kwargs

`_call_comfy_node` no longer maps link slots or widgets positionally onto `arg_names`. Link inputs go through `_linked_kwargs_by_name`, which for each resolved slot reads `node["inputs"][slot]["name"]` and passes that as the kwarg only if it appears in the node's INPUT_TYPES (`argset`). The slot-index fallback is retained solely for the case where the JSON lacks a socket name, which does not occur for this workflow's nodes.

The three complex nodes are routed through `_custom_node_kwargs`, which returns a non-None dict and short-circuits the positional widget fill: LTXDirector 131 passes only linked inputs plus name-matched timeline scalars, then explicitly pops `optional_latent`/`global_prompt`; rgthree 138 passes only linked model/clip and never feeds its dynamic-widget dicts to arg names (falling to `apply_rgthree_lora_fallback` with parsed strengths, logged per Section 6, if the bare call fails); VHS_VideoCombine 139 intersects its dict-form `widgets_values` with `arg_names` by name, dropping UI-only keys.

The one new wrinkle is the LTXDirector `candidates` dict:

```python
candidates = {
    "frame_rate": tl.get("fps"), "fps": tl.get("fps"),
    "duration": tl.get("duration"), "frames": tl.get("frames"),
    "length": tl.get("frames"),
}
for name, val in candidates.items():
    if name in argset and name not in kwargs and val is not None:
        kwargs[name] = val
```

This guesses several plausible arg names and applies whichever the live INPUT_TYPES happens to declare. It is guarded three ways so it cannot overwrite a linked input or invent an argument the node doesn't declare — but it is a guess: the node parses its full timeline from the serialized `widgets_values[6]` JSON string, so it very likely does not need these scalars injected separately, and if two candidate names both matched (e.g. `fps` and `frame_rate`) both would be set. Low risk given the guards, but it is the one place the fix adds speculation rather than removing it. Tightening to linked-inputs-only would be cleaner.

### Issue 5 fix — checkpoint resume is now honest

`ensure_node_executed` now calls `_try_restore` before executing. `_try_restore` returns True only when the checkpoint marks the node complete *and* its output is live in `self.node_outputs` (same process); otherwise it logs that it is re-executing because outputs are non-serializable tensors and returns False. The net behavioral change on restart is a truthful log line plus deliberate re-execution — no fake skip that would hand a downstream node a `None`. The `CheckpointManager` docstring was rewritten to describe a progress log rather than cached compute.

### Issue 6 fix — honesty block covers the real risk surface

Section-40 now lists two additional NOT-verified items: faithful custom-node execution (arg names only known once packages import on Colab; unmapped args fall back to node defaults; for 138 to the logged builtin-LoraLoader path; explicitly "NOT a guarantee of byte-identical custom-node semantics") and checkpoint resume re-executing across a restart. Both verified present in the `--validate-only` output.

### Regressions checked

No forbidden V2/V3 patterns reintroduced (Section-41 by-construction checks still pass: no 5-segment loop, no linear_blend_overlap, no per-scene latents, no post-only mux, no silent swallowing, no placeholder images). Issue 3 (stage labels) and issue 4 (unlinked optional sockets) are resolved and covered in the high-level view. The rgthree fallback's `resolved_inputs.get(0)/.get(1)` is the only place a by-slot index survives; for node 138 the inputs are `model`,`clip` in that order and both linked, so it resolves correctly, but it is inconsistent with the by-name discipline now used everywhere else and would be worth aligning. Section-27 remains all-9-PASS and Section-41 52/52, so the fixes did not break any derived assertion.
